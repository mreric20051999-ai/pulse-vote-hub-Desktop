Pulse Vote Hub Desktop

Offline Desktop Election App — School & Station Elections Only

Electron Offline-First SQLite Windows + macOS

What This Is

A standalone Electron desktop app for running school and station elections completely offline. No internet required. No Firebase required. Multiple devices at the same location connect over local network (LAN) with one device acting as the server. Results from different locations are exported as files and manually combined later.

How LAN Sync Works

StepWhat Happens
1. Start appFirst device to start becomes the SERVER (hosts Express + WebSocket)
2. Join networkOther devices auto-discover the server via mDNS and connect as CLIENTS
3. Cast voteClient sends vote → Server validates (duplicate check) → Server stores in SQLite → Server broadcasts to all clients
4. Real-time updateAll connected devices see the vote count update instantly
5. Server goes downClients cache votes locally in SQLite, auto-reconnect when server returns
6. Export resultsServer exports full results as JSON → USB → Merge tool on admin PC

Database Schema (SQLite)

-- Coordinator credentials (set on first run)
CREATE TABLE config (
  key TEXT PRIMARY KEY,
  value TEXT
);

-- Election officers (Coordinator + Assistant roles)
CREATE TABLE officers (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  officer_id TEXT UNIQUE NOT NULL,
  password TEXT NOT NULL,
  role TEXT CHECK(role IN ('coordinator', 'assistant')) DEFAULT 'assistant',
  assigned_device TEXT,
  created_at INTEGER
);

-- Election definition
CREATE TABLE elections (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  type TEXT CHECK(type IN ('school', 'station')),
  status TEXT CHECK(status IN ('setup', 'voting', 'closed')) DEFAULT 'setup',
  created_at INTEGER,
  closed_at INTEGER
);

-- Positions within an election
CREATE TABLE positions (
  id TEXT PRIMARY KEY,
  election_id TEXT REFERENCES elections(id),
  title TEXT NOT NULL,
  max_votes INTEGER DEFAULT 1
);

-- Candidates
CREATE TABLE candidates (
  id TEXT PRIMARY KEY,
  election_id TEXT REFERENCES elections(id),
  position_id TEXT REFERENCES positions(id),
  name TEXT NOT NULL,
  photo_path TEXT,
  sort_order INTEGER
);

-- Voters
CREATE TABLE voters (
  id TEXT PRIMARY KEY,
  election_id TEXT REFERENCES elections(id),
  voter_id TEXT NOT NULL,
  name TEXT,
  password_hash TEXT NOT NULL,
  password_salt TEXT NOT NULL,
  assigned_station TEXT,
  has_voted INTEGER DEFAULT 0,
  voted_at INTEGER,
  position_voted TEXT
);

-- Check-in records
CREATE TABLE checkins (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  election_id TEXT,
  voter_id TEXT NOT NULL,
  officer_id TEXT,
  device_id TEXT,
  timestamp INTEGER,
  hash TEXT,
  UNIQUE(election_id, voter_id)
);

-- Cast votes (hash-chained, append-only)
CREATE TABLE votes (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  election_id TEXT,
  position_id TEXT,
  candidate_id TEXT,
  voter_id TEXT,
  device_id TEXT,
  station_id TEXT,
  timestamp INTEGER,
  prev_hash TEXT,          -- hash of previous vote (hash chain)
  vote_hash TEXT,          -- hash of this vote's data
  signature TEXT,          -- digital signature (if enabled)
  synced INTEGER DEFAULT 0
);

-- Immutable audit log (hash-chained)
CREATE TABLE audit_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  election_id TEXT,
  officer_id TEXT,
  action TEXT,
  details TEXT,
  timestamp INTEGER,
  prev_hash TEXT,
  entry_hash TEXT
);

Phase 3: Security & Integrity — 4-5 days🟡 Partial

Core security layer — protect votes, credentials, database, network, and audit trail.

TaskDetail
Password hashingbcrypt/argon2 for all officer + voter passwords — never plaintext
Vote hash chainEach vote stores hash of previous vote + salt — tampering breaks chain and is detected
Audit hash chainImmutable audit log — each entry hash-chained, append-only, can't be modified
DB encryptionEncrypt SQLite file with sqlcipher (AES-256) — stolen file is unreadable
Atomic vote transactionDuplicate check + vote write in one SQLite transaction — can't be interrupted
Vote signaturesEach vote digitally signed with app key (HSM/OS keychain)
Integrity verificationOn start/close, verify full hash chain + PRAGMA integrity_check — detects tampering
Login lockout5 failed attempts → 5-minute lockout — brute force protection
Role-based accessCoordinator = full, Assistant = check-in only — enforced server-side
Audio-visual feedbackConfirmation + error sounds; visual status for integrity checks

Deliverable: Elections run with tamper-evident vote records, encrypted DB, and full audit trail.

Built so far: scrypt password hashing (crypto.scryptSync), vote + audit hash chains, atomic vote transactions, role-based access. Still to do: DB encryption (sqlcipher/AES-256), digital vote signatures, on-start/close integrity verification, 5-attempt login lockout, confirmation/error sounds.
